# 品牌 HTML 管理一期设计

## 目标与边界

为组织部门维护可检索、可预览的品牌 HTML 页面。后台管理员负责上传、关联部门和替换；工作台用户只能查找并打开自己直接归属部门的页面。

- 唯一关系：同一组织部门下，一个品牌只对应一个最新 HTML 文件；不同部门可以使用相同品牌名。
- 上传必须选择一个存在且启用的组织部门。
- 用户多部门归属按精确部门 ID 合并可见范围，不继承父部门或子部门。
- 管理员可见全部；迁移前未关联部门的旧页面仅管理员可见。
- 仅接收 `.html` / `text/html` 文件，不限制单文件大小。
- 不处理 HTML 所依赖的本地图片、CSS、JavaScript 等额外文件；支持自包含 HTML 与公网资源。
- 删除品牌页面时同时删除业务关联，已存文件保留于现有文件库以避免误删共享资产。

## 数据与接口

新增 `brand_html_page` 表：`id`、`brand_name`、`department_id`、`file_id`、`file_name`、`created_by`、`created_at`、`updated_at`、`deleted_at`；`department_id + brand_name` 联合唯一。

- `GET /api/brand-pages`：登录用户检索可访问品牌页面，支持 `keyword` 和 `departmentId`。
- `GET /api/brand-pages/{id}`：读取页面元数据。
- `GET /api/brand-pages/{id}/content`：以 `text/html` 内联响应文件内容，用于 iframe 渲染。
- `POST /api/admin/brand-pages`：管理员通过 `departmentId + brandName + file` 上传，并按部门和品牌创建或替换页面。
- `PUT /api/admin/brand-pages/{id}`：管理员编辑组织部门、品牌名称，并可选择是否替换 HTML 文件；不上传文件时保留原文件。
- `DELETE /api/admin/brand-pages/{id}`：管理员删除品牌页面关联。

上传接口使用 multipart；后端校验文件非空和 `.html` 扩展名，并从已存储文件读取内容。品牌页面作为内部受信内容，通过无 `sandbox` 限制的 iframe 加载，允许脚本、表单、弹窗和顶层导航等 HTML 能力。

## 权限

新增两个权限点：

- `brand:page:read`：查看品牌 HTML 页面、搜索结果与预览。
- `admin:brand-page:write`：后台上传、替换、删除。

后台菜单仅对具备写权限的用户展示；工作台入口仅对具备读权限的用户展示。管理员种子角色自动包含这两个权限。列表接口和内容直链接口复用同一数据权限策略，越权直链返回 403。

## 界面与流程

后台新增“品牌 HTML”列表：每行展示品牌、组织部门、文件名、更新时间、上传人；上传和编辑弹窗通过组织树必选部门，编辑时 HTML 文件可选，删除使用确认框。

工作台新增“品牌页面”页面：可按用户有权访问的组织部门和品牌关键字筛选。点击结果进入 `/workbench/brand-pages/{id}`，隐藏平台侧栏并使用占满视口、不限制脚本能力的 iframe 加载认证后取得的 HTML 内容；悬浮操作提供返回和浏览器全屏。从后台进入预览时附带 `from=admin` 来源，返回按钮回到后台品牌列表。

## 错误处理与验收

- 部门、品牌名或文件为空，部门不存在/已禁用，或文件类型不合法时，上传接口返回可读错误。
- 同部门同品牌上传不新增第二条记录，而是原子替换为最新文件。
- 普通用户的列表、筛选和内容直链只能命中本人直接归属部门；多部门取并集，父子部门不继承。
- 页面记录或源文件不存在时返回 404；无权限返回 403。
- 删除后不再能通过搜索或直接 URL 打开。
- 页面刷新保留当前品牌页面路由，正常重新获取数据。
