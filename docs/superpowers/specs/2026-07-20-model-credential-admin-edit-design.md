# 模型调用凭证后台编辑设计

## 1. 背景与目标

当前“模型配置”后台已经展示模型、API 中转地址和脱敏后的 API Key，并且后端 `PUT /api/admin/model-configs/{configId}` 已具备更新和加密保存凭证的基础能力，但前端只有启用/停用入口，无法编辑配置。

本次目标是在不改变模型调用逻辑和供应商适配器的前提下，为具有模型管理权限的管理员提供安全的编辑入口，可修改模型名称、中转地址、供应商 Token、超时时间和重试次数。

## 2. 功能边界

### 2.1 包含范围

- 在模型配置列表操作列增加“编辑”按钮。
- 点击“编辑”打开与现有后台一致的居中弹窗。
- 弹窗允许修改：
  - 模型名称；
  - API 中转地址；
  - 新 Token；
  - 超时时间；
  - 重试次数。
- 弹窗只读展示供应商、模型类型和配置 ID。
- 保留列表原有的启用/停用功能。
- 只有 `admin:model:write` 权限可以看到并调用编辑入口。

### 2.2 不包含范围

- 不新增或删除模型配置。
- 不编辑供应商、模型类型、配置 ID 和供应商扩展参数。
- 不展示、复制或导出现有明文 Token。
- 不提供清空 Token 的操作。
- 不调整内部模型调用、路由选择、供应商适配器和业务 UI。

## 3. 交互设计

模型列表每行的操作列依次展示“编辑”和现有的“启用/停用”。点击“编辑”后，先将当前普通配置复制到独立表单，再打开居中弹窗。

弹窗字段如下：

| 字段 | 类型 | 初始值 | 是否可编辑 |
|---|---|---|---|
| 配置 ID | 文本 | 当前配置值 | 否 |
| 供应商 | 文本 | 当前配置值 | 否 |
| 模型类型 | 文本 | 当前配置值 | 否 |
| 模型名称 | 文本输入 | 当前配置值 | 是 |
| API 中转地址 | URL 输入 | 当前配置值 | 是 |
| 当前 Token | 脱敏文本 | `apiKeyMasked` | 否 |
| 新 Token | 密码输入 | 空 | 是 |
| 超时时间 | 数字输入 | 当前配置值 | 是 |
| 重试次数 | 数字输入 | 当前配置值 | 是 |

新 Token 输入框提示“留空则保留现有 Token”，关闭浏览器自动填充。保存期间禁用关闭、取消和保存按钮，防止重复提交。保存成功后清空 Token 表单、关闭弹窗、刷新模型列表当前页并显示成功提示；保存失败时保持弹窗和输入内容，显示可读错误。

## 4. 数据流

```text
点击编辑
   ↓
复制当前脱敏配置到独立表单
   ↓
修改普通字段，可选填写新 Token
   ↓
前端校验并构造请求；Token 留空时省略 apiKey
   ↓
PUT /api/admin/model-configs/{id}
   ↓
后端权限校验 → 参数校验 → Token AES-GCM 加密
   ↓
更新数据库 → 写不含凭证的操作日志 → 返回脱敏配置
   ↓
前端清空敏感表单并刷新当前列表页
```

## 5. 接口与校验

沿用现有接口：

```http
PUT /api/admin/model-configs/{configId}
Authorization: Bearer <session-token>
Content-Type: application/json
```

请求只包含本次允许编辑的字段。新 Token 为空时不发送 `apiKey`；后端继续保留原有加密凭证。

校验规则：

- `modelName`：必填，保存普通文本字段时去除首尾空格。
- `apiBaseUrl`：非空时必须使用 `http://` 或 `https://`；空值保持原配置不变。
- `timeoutSeconds`：1–600。
- `retryCount`：0–5。
- `apiKey`：空白或缺失时保留原值；非空时最大 8192 字符，凭证内容不做裁剪或格式转换。
- 路径中的 `configId` 必须对应现有模型配置。

前端校验用于即时反馈，后端重复执行同一套边界校验并作为最终约束。后端权限继续由 `admin:model:write` 强制校验。

## 6. 安全设计

- 后端使用现有 `SecretCrypto` AES-GCM 加密 Token 后落库。
- API 列表和更新响应只返回 `apiKeyMasked`，禁止返回 `apiKey` 或 `encryptedApiKey`。
- Token 不写入操作日志、错误信息、控制台日志和前端持久化存储。
- 操作日志只记录配置 ID、模型名称和“修改模型配置”动作。
- 前端关闭弹窗或保存成功后清空敏感字段。
- 只读权限仅能查看脱敏信息，不展示“编辑”和“启用/停用”。

## 7. 错误处理

- 参数错误返回 400，并提供可映射到字段的中文错误信息。
- 无写权限返回 403，前端提示“无模型管理权限”，不得改变本地列表。
- 模型配置不存在返回 400 或项目现有统一的不存在错误响应。
- 数据库或服务异常由统一异常处理返回安全错误，不泄露 SQL、密文或明文凭证。
- 请求失败时弹窗保持打开；重复保存由前端提交锁拦截。

## 8. 性能与复杂度

- 打开编辑弹窗只复制当前行对象，不额外请求详情接口。
- 单次保存执行一次内存配置查找和一次数据库更新，时间复杂度 O(1)。
- 保存完成后只刷新当前模型列表页，不增加全后台数据加载。
- 不引入新的运行时依赖。

## 9. 测试与验收

### 9.1 前端

- `admin:model:write` 用户看到“编辑”按钮，只读用户看不到编辑和启停入口。
- 弹窗回填普通字段和脱敏值，但新 Token 始终为空。
- Token 留空时请求体省略 `apiKey`；填写时才发送。
- 保存期间关闭、取消和保存均不可操作，重复点击只发起一次请求。
- 保存成功清空敏感字段、关闭弹窗并刷新当前页。
- 保存失败保持弹窗与输入内容，并展示错误。
- 非法 URL、超时和重试次数在提交前被拦截。

### 9.2 后端

- 更新普通字段时保留原加密 Token。
- 更新 Token 后数据库只保存 `enc:v1:` 密文。
- 列表和更新响应均不包含明文 Token 或密文。
- 空 Token 不覆盖原凭证。
- 超长 Token、非法 URL、超范围超时和重试次数返回 400。
- 无 `admin:model:write` 权限返回 403。
- 操作日志不包含 Token。

### 9.3 验收结果

管理员可从模型配置列表打开编辑弹窗并安全更新模型连接信息；现有模型调用逻辑不变，凭证不会通过页面、接口响应或日志泄露。

## 10. 方案选择记录

已评估三种方案：

1. 表格“编辑”按钮加居中弹窗：入口明确，与现有后台交互一致，选用。
2. 操作菜单加分组弹窗：信息层级清晰，但入口隐藏且对当前字段规模偏重。
3. 列表行内编辑：操作快，但破坏列表密度，也违反现有“新增/编辑使用弹窗”的约定。
