# 详情页统一身份接口接入说明

本文面向详情页服务端开发者。工作台负责登录身份、组织和角色；详情页负责本地项目、素材、16 项功能权限及设计、训练等专项能力。本接口不下发详情页功能权限，也不要求迁移现有权限数据。

## 接入顺序

1. 用户从工作台「详情页制作」入口进入。工作台签发 `detail-page-sso` 一次性票据，浏览器跳转详情页 `/platform-entry?ticket=...`。
2. 详情页服务端使用服务凭据调用 `POST /api/tool-sessions/exchange`，提交票据和 `toolKey=detail-page-sso`，取得 `toolSession`、`userId`、`projectId` 和 `expiresAt`。票据只能兑换一次。
3. 详情页服务端使用同一服务凭据和 `toolSession` 调用 `POST /api/tool-sessions/detail-page-context`，取得当前用户身份、组织和有效角色。建立本地会话时校验返回的 `userId` 与票据兑换结果中的 `userId` 一致。
4. 详情页后续需要判断当前身份或角色时，服务端重新查询上下文，并按稳定 `userId` 校验本地映射。工作台会话失效后要求用户重新从工作台入口进入，不使用旧登录回退。

工作台项目 `projectId` 用于工具会话范围与运行审计，不是详情页内部项目 ID。详情页原有项目和素材仍关联原本地用户 ID；映射只按工作台稳定 `userId` 建立，不按姓名、账号或邮箱自动合并。

## 请求与响应

请求仅由详情页服务端发起，不需要请求体：

```http
POST /api/tool-sessions/detail-page-context HTTP/1.1
Authorization: Bearer <两端约定的服务凭据>
X-Tool-Session: <票据兑换得到的工具会话>
```

成功响应示例：

```json
{
  "active": true,
  "userId": "u_example",
  "account": "example",
  "name": "示例用户",
  "departmentKeys": ["visual"],
  "roleCodes": ["member"],
  "toolKey": "detail-page-sso",
  "projectId": "tool_project_example",
  "expiresAt": "2026-10-21T10:00:00Z"
}
```

| 字段 | 含义 |
| --- | --- |
| `active` | 请求成功时为 `true`；失效会话直接返回错误，不返回 `active: false`。 |
| `userId` | 工作台稳定用户 ID，是用户映射的唯一依据。 |
| `account`、`name` | 当前账号与姓名，可能变化，不用作映射键。 |
| `departmentKeys` | 用户直接归属的部门 ID 列表，与目录接口 `departments[].id` 使用同一套 ID；为空表示没有归属。列表可有多个部门，不包含自动展开的下级部门。 |
| `roleCodes` | 当前已启用且未删除的工作台角色编码列表。管理员编码为 `admin`，部门负责人编码为 `department_leader`，普通成员编码为 `member`；用户可有多个角色，应检查列表是否包含目标编码，不能只读第一项。 |
| `toolKey`、`projectId` | 本次工具会话的工具和工作台项目范围，应与票据兑换结果一致。 |
| `expiresAt` | 工具会话到期时间，ISO 8601 UTC 格式。 |

详情页如何根据工作台角色显示管理入口，以及如何组合本地功能权限，由详情页自行决定。现有通用 `/api/tool-sessions/introspect` 会限制工具会话中的管理员角色，不适合用来判断详情页管理员身份；应使用本文的专用接口。

例如，部门负责人可能返回 `"roleCodes": ["department_leader", "member"]` 和 `"departmentKeys": ["design"]`。`departmentKeys` 直接对应目录中的部门 ID，不需要名称映射；如果某个 ID 在当前目录中已不存在或已停用，详情页不得用它授予部门管理范围。

## 组织目录全量同步

详情页服务端可定期调用 `POST /api/tool-sessions/detail-page-directory`，获取工作台当前的部门树、用户基本信息和用户部门归属。此接口只校验服务凭据，不需要用户工具会话，适合后台同步任务；不得从浏览器直接调用或将完整目录原样下发给普通用户。

```http
POST /api/tool-sessions/detail-page-directory HTTP/1.1
Authorization: Bearer <两端约定的服务凭据>
```

成功响应示例：

```json
{
  "generatedAt": "2026-10-22T00:00:00Z",
  "departments": [
    {"id": "design", "parentId": null, "name": "设计部", "enabled": true, "sortOrder": 10},
    {"id": "visual", "parentId": "design", "name": "视觉组", "enabled": true, "sortOrder": 20}
  ],
  "users": [
    {"userId": "u_example", "account": "example", "name": "示例用户", "enabled": true},
    {"userId": "u_leader", "account": "leader", "name": "部门负责人", "enabled": true},
    {"userId": "u_admin", "account": "admin", "name": "管理员", "enabled": true}
  ],
  "memberships": [
    {"userId": "u_example", "departmentId": "visual", "primary": true},
    {"userId": "u_leader", "departmentId": "design", "primary": true}
  ],
  "managerScopes": [
    {"userId": "u_leader", "scope": "DEPARTMENT", "managedDepartmentIds": ["design", "visual"]},
    {"userId": "u_admin", "scope": "ALL", "managedDepartmentIds": ["design", "visual"]}
  ]
}
```

`departments` 使用工作台组织部门 ID；`parentId: null` 表示根部门。`memberships` 是用户与部门的直接归属，一人可有多个部门，`primary` 标记主部门。接口包含停用的部门和账号，并通过 `enabled` 明确标记；已删除的部门和账号不返回，关联它们的归属也不返回。详情页应以每次完整响应更新目录缓存；缺失项应标记为不再有效，不直接删除详情页项目或素材，并仅对启用的部门及账号授予业务访问。

`managerScopes` 是工作台按当前有效角色及部门归属计算的管理范围，仅列出启用的管理员和部门负责人。`scope=ALL` 的管理员覆盖所有启用且上级链均启用的部门；`scope=DEPARTMENT` 的负责人覆盖其直接归属部门及启用的下级部门。没有部门归属的负责人会得到空列表。停用部门及其下级部门不进入管理范围。详情页判断当前用户为负责人时，必须先确认身份接口的 `roleCodes` 包含 `department_leader`，再按稳定 `userId` 查找其 `managerScopes`；管理员同理先确认 `admin`。不能仅凭目录里存在一条管理范围记录升级用户角色。目录数据本身不授予详情页管理权限或 16 项功能权限。

服务凭据由两端服务器配置人员通过既有安全渠道配置，接入文档和聊天中不提供实际值。目录接口的服务凭据无效时返回 `403`，同步失败时不得用旧缓存扩大授权范围。

## 校验与错误处理

身份接口会在每次调用时检查账号是否启用、源登录会话和工具会话是否有效、工具是否启用、用户是否仍可使用工具，以及工作台项目范围。身份接口只接受 `detail-page-sso` 工具会话；目录接口仅接受有效服务凭据。

| HTTP 状态 | 场景 | 详情页处理 |
| --- | --- | --- |
| `401` | 工具会话过期、被撤销，或源登录会话失效。 | 清除详情页本地会话，提示从工作台重新进入。 |
| `403` | 服务凭据无效，或工具会话不属于详情页。 | 拒绝访问并记录服务端诊断信息；不回退本地角色。 |

请求失败时不使用上次缓存的角色继续放行。服务凭据和工具会话只保存在服务端，不发送给浏览器、不记录到日志。工作台配置项为 `APP_TOOL_SESSIONS_SERVICE_CREDENTIAL`（兼容 `APP_TOOL_SESSION_SERVICE_CREDENTIAL`）；详情页使用与其相同的 `WORKBENCH_SERVICE_CREDENTIAL`。

## 联调检查

- 工作台管理员、普通成员及多角色用户分别调用接口，核对 `roleCodes`、`departmentKeys` 和稳定 `userId`。
- 在工作台禁用角色、账号或工具，以及撤销源登录会话后重新调用；失效身份不得继续通过。
- 用其他工具的会话调用此接口，必须被拒绝。
- 详情页核对原有用户映射和本地项目归属；16 项功能权限继续按详情页现有数据处理。
- 同步组织目录，核对根部门、下级部门、多部门用户、负责人范围、停用账号或部门和已删除记录的处理。
