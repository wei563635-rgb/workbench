# 已删除账号名称复用

工作台允许新用户使用已软删除用户的账号名。旧用户记录、用户 ID 和历史业务归属保留；新用户取得新的用户 ID。登录、用户列表和管理缓存只识别未删除用户。同一时间仍只允许一个未删除用户使用同一账号名。

## 数据库前置迁移

生产 PostgreSQL 的旧约束 `sys_user_account_key` 对全部记录生效。发布新版后端前，由 `sys_user` 表所有者执行 [迁移 SQL](../../backend/src/main/resources/db/manual/20261022_active_user_account.sql)。迁移先建立仅约束 `deleted_at IS NULL` 的唯一索引，再移除旧约束。应用账号若不是表所有者，不要依赖应用启动时完成这项 DDL。

执行前确认当前完整 JAR 的源码提交、`sys_user` 表所有者、旧约束名称和未删除账号没有重名；备份工作台数据库、当前完整 JAR 及受限配置。SQL 设置 5 秒锁等待上限，失败时停止发布并核对数据库状态。迁移后确认新索引唯一且带 `deleted_at IS NULL` 条件，旧约束已移除，再切换由目标源码提交构建的完整 JAR。

## 验收与回退

通过管理界面新建一个与已删除用户同名的账号，核对新旧用户 ID 不同、旧用户仍处于删除状态、新用户可用新密码登录、历史项目和会话未转给新用户。再尝试创建同名未删除用户，必须返回“账号已存在”。核对未删除用户列表没有重复账号。

若应用验证失败，恢复上一版完整 JAR。回退应用时保留新的部分唯一索引：旧版仍能读取和登录未删除账号；一旦发生过账号名复用，直接恢复全表唯一约束会失败，也不能删除或改写新用户记录来强行回退。数据库需要回退时，先单独评估复用后产生的记录和业务归属。
