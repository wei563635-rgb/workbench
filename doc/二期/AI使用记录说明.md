# AI 使用记录

## 入口与权限

后台「使用记录」替换原「AI 日志」页面，提供「全部」「Key 调用」「工作台调用」分类。仅当前持有启用的内置 `admin` 角色的超级管理员可访问；通用日志权限、部门负责人或工具会话不授予访问权。原 `/api/admin/ai-call-logs` 保留兼容，读取权限同步收紧。

页面支持时间、用户姓名或账号、部门、模型、工具、状态及请求 ID 查询，默认最近 7 个北京时间自然日，每页 20 条。列表不返回正文，详情按需读取并记录操作审计。未知用量显示「未提供」，与真实零用量区分；历史「已计量」不推断为成功。

Key 调用按中转登记的 Key 用途识别。工作台调用包括工作台网关直连供应商及内部中转 Key 的调用。客户端自行提交的内部来源、运行 ID 和调用 ID 不能把个人 Key 调用伪装成工作台调用。未通过身份验证的请求不猜测用户。

## 正文阅读

详情优先展示输入与 AI 回答，按用户、AI、系统指令和工具结果分段。支持工作台参数包装、OpenAI Chat / Responses、Claude、Gemini 文本以及常见 SSE 流式片段合并；最终快照替换增量，避免答案重复。异步结果、供应商响应、图片及具体错误按实际保存内容展示，不补造缺失正文。

正文支持 Markdown 标题、列表、表格和代码块，禁用原始 HTML 与脚本链接。超长文本只渲染前 60,000 个字符并明确提示，完整数据保留在默认折叠的「原始请求与响应」中；未知格式保留原文。调用元数据折叠在「调用信息」中，采集、权限及计量规则保持一致。

返回正文中的 JSON 对象、JSON 代码块及非标准响应，按字段和值、分组和列表阅读，原始内容仍可展开核查。支持任务 `result` / `body` 包装及已保存的 Coze 消息列表。仅保存了任务状态与用量的旧 Coze 记录明确提示回答正文未保存，不将任务完成推断为已保存回答；历史缺失正文不做补造。

## 采集与计量

工作台在 MVC 鉴权及模型执行之前建立调用记录，并在响应结束后保存结果。中转在 Key 鉴权和额度准入之前建立独立调用记录，覆盖鉴权失败、额度与并发拒绝、上游失败及无原生用量 ID 的请求。该记录独立于配额事实表，不参与额度扣减。

工作台通过服务端生成的调用 ID 关联中转事件。相同调用、重试同步和迟到用量合并至同一索引记录；普通客户端不能指定这个关联关系。上游账号的请求尝试作为详情中的元数据展示，最多保存 100 次并标注可能截断，不保存其鉴权头、代理配置或秘密。

异步图片提交显示处理中，工作台任务查询和中转原生图片任务完成会更新原记录，不增加调用次数。其他已关联异步任务在授权查询返回终态时回写。任务在没有可靠终态时保留处理中或结果未知，不仅凭提交成功推断生成成功。流式响应检查结束和错误事件，缺少结束事件显示结果未知。

Token、图片数以实际提供的数据和原生计量事实为准。供应商只返回预扣积分时，页面明确说明实际消耗未提供。该页面不会修改员工额度、供应商计费或已有统计的权威来源。

## 接口与数据

- `GET /api/admin/ai-usage-records`：分页列表。参数为 `page`、`pageSize`、RFC 3339 `from` / `until`（前闭后开）、`channel`（`key` / `workbench`）、`user`、`userId`、`departmentId`、`model`、`toolKey`、`status`、`requestId`。响应包含 `items`、`page`、`pageSize`、`total`、`sync` 和历史覆盖说明。
- `GET /api/admin/ai-usage-records/{id}`：元数据、输入参数、响应、异步结果及上游尝试。无法读取正文时返回明确的可用性说明。两种接口均设置 `Cache-Control: no-store`。
- 中转新增 `GET /api/v1/admin/workbench/calls` 和 `/calls/{id}/audit`；`capabilities.callRecords=true` 表示支持独立调用记录。事件列表使用更新时间窗口和变更游标，正文只通过详情接口读取。

工作台新增统一记录索引、历史导入标记及异步任务关联表。中转新增调用、任务结果和尝试表，继续使用原生用量及配额表。工作台默认每 60 秒同步中转，并重叠查询最近 2 小时，支持迟到计量和同步重试；同步失败不推进成功检查点。历史日志每轮有界导入，未完成期间列表可能仍在补齐。

新调用的完整内容仅进入加密记录；原 AI 日志保留计量元数据。正文在写入及历史读取时脱敏，不保存请求鉴权头。工作台沿用 AI 主密钥，中转沿用审计密钥；未配置可用加密密钥时不保存明文正文。正文超过大小限制、未读取、截断、保存失败或过期时不能作为完整凭证。正文读取和清理按 180 天限制，元数据保留用于历史查询；异步任务结果同样清理。图片保留供应商链接或已保存的 Base64 数据；仅 PNG、JPEG、GIF、WebP 栅格图片可内联预览，不执行 SVG 或任意 data URL。`b64_json` 按图片展示，支持点击放大和下载，编码保留在原始数据中；无效或截断编码显示原因。外部图片链接不保证永久有效，返回中的 Unix 秒／毫秒及 ISO 时间按北京时间显示。

历史仅导入已保存的工作台调用及中转用量，关联不明处不按时间或提示词猜测。详情页直连百炼 Embedding、Google Cloud Vision 不在本期范围内。历史缺失的失败请求、过期正文不能补造。WebSocket 不增加工作台托管员工的支持范围，仍按原有准入规则拒绝；该拒绝纳入记录。

## 构建与验收

本次不直接发布生产。发布前需备份受影响数据库，按完整制品流程发布中转、工作台后端及前端，并验证身份标记、接口能力和同步状态。旧制品回滚不删除新增日志表，不以恢复旧数据库覆盖发布后的业务数据。

生产中转源码扩展入口为 `python3 integrations/sub2api-workbench/apply_usage.py <干净源码检出目录>`，固定完整基线 `278d7090a037ba3bd53d82ab83f3087c83d86858`，保留已发布 Evolink 功能。脚本先核验全部目标文件，再修改源码，不能重复执行或套用其他基线。面向原始固定上游的 `apply.py` 同样包含记录能力，但不能用于覆盖现有生产定制源码。

验证命令：

```bash
mvn -f backend/pom.xml test
mvn -f backend/pom.xml -DskipTests package
cd frontend
npm test
npm run build
```

中转在隔离 PostgreSQL 下配置 `WORKBENCH_TEST_DSN`，执行 `go test ./internal/workbench -count=1` 和 `go test -tags=unit ./internal/server/middleware ./internal/service ./internal/handler ./internal/repository -count=1`。中间件测试须带 `unit` 标签和隔离数据库，不能用关闭配额校验的方式使测试通过。随后按固定上游流程构建嵌入原生前端的完整 Linux 制品。

本地协议和数据库测试验证采集、去重、权限、加密、异步回写和额度不变；不能替代真实供应商验收。测试环境还需分别发起真实工作台文本、图片及个人 Key 请求，核对完整输入产出、状态、权威用量和同步后的唯一记录，再进入发布审批。
