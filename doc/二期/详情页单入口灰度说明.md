# 详情页工作台单入口

本文件是工作台侧详情页登录与 AI 调用的维护入口。修改票据、用户映射、项目、模型或发布前，同时核对详情页仓库的 `docs/工作台接入与用户映射.md`。生产配置和密钥不写入工程文档。

## 登录与项目

工作台只展示一个「详情页制作」入口。工具卡片可省略项目 ID；服务端为用户按需创建隐藏的个人工具项目，用于票据范围、运行记录和用量审计。显式项目任务沿用所选项目。所有获授权用户均由 `POST /api/tool-sessions/detail-page-entry` 签发 `detail-page-sso` 一次性票据，进入详情页 `/platform-entry`。旧的按用户 ID 灰度名单不再决定入口；详情页 `/legacy-entry` 和本地密码登录已经停用。

工作台项目不映射成详情页项目。详情页内部项目、素材仍归属详情页本地用户；工作台用户与本地用户只按稳定 ID 建立映射，不按用户名自动合并。现存本地密码会话不能继续访问详情页业务接口。

工作台提供详情页专用身份接口 `POST /api/tool-sessions/detail-page-context`，返回用户稳定 ID、账号、名称、部门、完整有效角色列表、工具项目范围及到期时间。接口不返回详情页功能权限；详情页原有 16 项功能权限及设计、训练等专项能力由详情页自行维护和校验，不迁移到工作台。请求格式、安全要求与示例见 [详情页统一身份接口接入说明](详情页统一身份接口接入说明.md)。

工作台另提供仅供详情页服务端同步的 `POST /api/tool-sessions/detail-page-directory`，返回完整组织部门树、用户基本信息、用户部门归属和管理员／部门负责人的启用部门范围。详情页结合当前角色自行执行管理权限；目录接口本身不授予详情页业务权限。

工作台先上线身份接口，再由详情页团队按接入说明改造其服务端。工作台不修改详情页代码、账号映射、项目或权限数据；两端发布和验收分别记录。

## AI 路由

详情页外部文案、视觉理解和生图调用经工作台 AI 网关，关联工作台运行记录，统一使用 `provider=sub2api` 的 GPT 模型。员工额度、权限、参数、内容安全或会话错误直接返回。仅当 OpenAI 主账号池整体不可用时，允许 Sub2API 按 [Evolink 受控兜底说明](Evolink受控兜底说明.md) 切换至同名模型备用上游；详情页和客户端不直连 Evolink，不切换 Gemini、Nexhina、豆包或其他供应商。

两端服务凭据必须一致：工作台优先读取 `APP_TOOL_SESSIONS_SERVICE_CREDENTIAL`，兼容旧的 `APP_TOOL_SESSION_SERVICE_CREDENTIAL`；详情页使用 `WORKBENCH_SERVICE_CREDENTIAL`。若两种工作台变量同时存在，部署前应核对它们相同，避免环境变量覆盖配置文件占位符后票据兑换失败。

工作台按模型名称和类型精确匹配已启用的 Sub2API 配置；`detail-page-sso` 不沿用其他工具「选首个同类型模型」的回退规则。预置模型名称分别为文本 `gpt-6-luna`、图片 `gpt-image-2.5-flare`。文生图调用中转 `/v1/images/generations`；带参考图的图生图转换为 `/v1/images/edits` 的 `images[].image_url`。实际部署前必须核对中转上游对这些模型及视觉输入、图片编辑的支持和账号权限。

本轮例外：百炼 Embedding 和 Google Cloud Vision 继续从详情页调用。它们不计入 Sub2API 额度；详情页本地仍保留其用量记录。图片上传、素材存储等非 AI 模型请求不属于统一模型调用。

## 验收与发布

1. 同时确认工作台和详情页源码提交、完整制品、部署配置及回滚制品；禁止单文件或 class 补丁。
2. 用有工具权限和可用中转额度的普通员工账号，从工作台入口验证票据登录、项目归属；直接访问旧登录接口、旧入口和使用旧本地会话均应被拒绝。
3. 分别发起真实文案、图片理解和生图请求，核对结果、工作台运行记录及 Sub2API 用量。验证 GPT 主池正常时不进入备用池、主池失效时仅按受控规则切换 Evolink 同名模型；员工额度或权限错误须明确返回，不得调用其他模型。
4. 单独验证百炼 Embedding 和 Google Cloud Vision 保持原路径。健康检查或入口跳转不能代替真实生成验收。

图像上游的模型权限和图生图兼容性需要在测试环境用真实账号验证；未通过时不得宣称该能力已完成接入。
