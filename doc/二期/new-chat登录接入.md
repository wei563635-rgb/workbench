# new chat 登录接入

工作台侧栏在「AI 内容部」之后、「通用与个人」之前新增独立入口，名称为 `new chat`，以新标签页打开。本次仅接入登录和角色；按用户确认，AI 保留现有 Key 及调用链路，不新增 AI 网关、运行记录、文件登记或项目关联。

## 身份接口

| 接口 | 身份与用途 |
| --- | --- |
| `POST /api/tool-sessions/new-chat-entry` | 工作台登录用户签发 60 秒有效的一次性票据；不需要请求体 |
| `POST /api/tool-sessions/new-chat-exchange` | newChat 服务端凭服务凭据兑换；请求体为 `{ "ticket": "..." }` |
| `POST /api/tool-sessions/new-chat-context` | newChat 服务端凭服务凭据和 `X-Tool-Session` 查询当前身份；无请求体 |

入口纳入角色的“工具访问权限”，工具标识为 `new-chat`。首次注册仅给管理员角色授权，其他角色由管理员勾选开放；重新启动不会补回已撤销的授权。无授权时隐藏独立侧栏入口，签发、票据兑换及每次身份查询都会实时拒绝访问；工具停用或维护时也拒绝进入。角色编辑使用完整工具目录，不要求操作者自身已获得该工具授权。new chat 不在 AI 内容部重复展示工具卡片。首次密码未修改时不得签发。兑换和身份查询复核原工作台登录是否有效；用户停用、注销或会话到期后拒绝访问。身份响应返回稳定用户 ID、账号、姓名、部门 ID 列表和完整有效 `roleCodes`，不返回项目。newChat 只将含 `admin` 的角色列表映射为管理员。

新增 `new_chat_login_ticket` 与 `new_chat_login_session` 两张表，不含项目字段。票据和会话只存 SHA256 哈希，票据通过事务与条件更新保证只兑换一次。会话有效期为 8 小时，同时受原工作台会话有效性约束。这类会话不能作为工作台业务 API 的登录凭证；原详情页和推广图工具协议不变。

工作台「退出」按钮先调用已有 `POST /api/auth/logout` 撤销服务端登录，再清理浏览器状态；已有登录失效返回 401 时也清理。网络或服务异常时提示退出失败并保留界面，不把仅清理浏览器状态当作注销成功。源会话撤销后，newChat 下一次身份查询即失败。

## 配置与发布

- 工作台新增 `APP_NEW_CHAT_ENTRY_URL`，填写 newChat 的公开根 URL，包含部署子路径并以斜杠结尾。未配置时入口返回 503，前端提示失败并关闭空白标签页。
- 工作台服务凭据沿用 `APP_TOOL_SESSIONS_SERVICE_CREDENTIAL`，兼容旧变量 `APP_TOOL_SESSION_SERVICE_CREDENTIAL`；与 newChat 的 `WORKBENCH_SERVICE_CREDENTIAL` 一致。
- newChat 配置、会话加密、Node 版本、数据库初始化和子路径构建见其 `docs/工作台登录接入.md`。连接入口及真实凭据只保存在仓库外，不写入本文。
- newChat 代理访问日志不得记录 `/platform-entry` 的查询串。两端只发布可追溯提交生成的完整制品。
- 首次登录接入会创建登录表；工具权限升级会注册 `new-chat` 工具并初始化管理员授权。两类发布均涉及数据库写入，发布前按工程测试发布流程备份受影响数据库并验证可读；不迁移 newChat 开发历史数据。

## 验收

工作台执行 `mvn test`、完整后端打包，以及前端 `npm test` 和 `npm run build`。新增集成测试覆盖无项目成员身份、无隐藏项目创建、管理员撤权、源登录注销、停用、票据过期与并发重放。newChat 另执行 `npm run check:workbench` 验证 HTTP 登录。

自动化与本地测试不能代替真实环境验收。发布后用已授权普通员工和管理员从侧栏进入，验证 Cookie、角色、退出及既有 AI 功能；未部署或未完成真实账号验收时应明确标记。

## 工具权限验收

- 首次部署或升级后，仅管理员默认拥有 `new-chat`，普通成员与部门负责人默认未授权。角色中勾选后可无项目进入；取消勾选、停用角色或停用工具后，签发、兑换和已有会话下一次身份读取均拒绝访问。
- 角色编辑从完整工具目录读取授权选项，撤掉操作者自身工具权限后仍可重新配置。new chat 保持侧栏独立入口，不在部门工具卡片中重复展示。
- 再次启动不恢复已取消的授权。升级前已经进入的非授权用户，下一次受保护访问会被拦截；已有内容不删除。
- 本地验证：后端 187 项、前端 225 项测试和完整构建通过；Ego 实际页面验证角色勾选、确认保存、重新打开、撤销授权及入口隐藏。敏感权限确认弹窗在角色编辑弹窗之上显示，避免保存操作被遮挡。此记录不代表已发布生产环境。
