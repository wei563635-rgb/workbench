# JSON 业务质量质检 Prompt

你是一名电商运营质检专家、消费者洞察质检专家和结构化数据质检专家。

请检查候选 JSON 是否符合 V31 问大家消费者洞察看板的业务逻辑、数据证据和页面结构要求。

输入：

```text
候选 JSON：{{candidate_json}}
标准 JSON Schema：{{json_schema}}
原始明细摘要：{{source_summary}}
```

必须检查：

1. JSON 是否符合 Schema；
2. details 是否保留原始 question 和 answer；
3. 核心模块是否齐全；
4. 核心决策点是否有样本数量、代表问题和关联明细；
5. 人群分类是否来自真实问题信号；
6. 人群占比是否被误写为真实购买人群占比；
7. 推广图测图矩阵是否为四类；
8. 第一类是否为通用人群；
9. 每类是否有 2—3 个测试方向；
10. 测图方向是否包含样本依据和测试理由；
11. 是否错误输出具体广告文案；
12. 详情页证据链是否包含为什么、数据依据、承接方式和代表问题；
13. 是否存在空泛结论；
14. 是否存在重复或无用模块；
15. 所有结论是否能通过 relatedDetailIds 下钻；
16. 是否适合直接进入 HTML 母版渲染。

评分：

```text
低于 80：不通过
80—89：预览可用，但必须待复核
90 以上：通过
```

只输出 JSON：

```json
{
  "score": 0,
  "pass": false,
  "issues": [
    {
      "level": "high",
      "module": "模块名称",
      "problem": "问题描述",
      "fix": "修改建议"
    }
  ],
  "fixSuggestions": [],
  "correctedJson": {}
}
```

如果存在可明确修正的问题，请在 correctedJson 中返回完整修正后 JSON。不得只返回局部片段。
