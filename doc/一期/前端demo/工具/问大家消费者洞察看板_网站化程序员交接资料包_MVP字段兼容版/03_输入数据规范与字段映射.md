# 输入数据规范与字段映射

## 1. 核心前提

问大家数据源格式允许不固定，系统不要求用户必须使用统一模板。

第一版只强制要求数据中必须能识别出两个核心字段：

```text
1. 消费者的问题 question
2. 他人的回答 answer
```

这两个字段是问大家消费者洞察分析的最低输入要求。其他字段如时间、商品名、SKU、平台、点赞数、回答数等均为可选字段。

## 2. 支持文件格式

| 格式 | 是否支持 | 说明 |
|---|---|---|
| .xlsx | 必须支持 | 推荐格式 |
| .xls | 建议支持 | 兼容旧版 Excel |
| .csv | 必须支持 | 需兼容 UTF-8 / GBK |
| .json | 二期可支持 | 用于系统对接 |
| .zip | 二期可支持 | 多文件批量上传 |

## 3. 最低必填字段

| 标准字段 | 是否必填 | 含义 | 示例 | 缺失影响 | 处理规则 |
|---|---|---|---|---|---|
| question | 必填 | 消费者原始问题 | 这个敏感肌能用吗？ | 无法分析消费者关注点 | 无法确认则阻断生成 |
| answer | 必填 | 他人回答 / 买家回答 / 商家回答 | 我用了还可以，不刺激 | 无法判断回答覆盖和证据链 | 无法确认则阻断生成 |

## 4. 可选字段

| 标准字段 | 是否必填 | 含义 | 示例 | 缺失影响 | 处理规则 |
|---|---|---|---|---|---|
| time | 可选 | 提问或回答时间 | 2026-06-01 | 无法做时间追溯 | 可为空 |
| productName | 可选 | 商品 / 产品名称 | 产品A | 标题和分组不完整 | 可用文件名或用户输入兜底 |
| sku | 可选 | SKU / 商品ID | SKU001 | 多商品分析受影响 | 单商品可为空 |
| platform | 可选 | 平台 / 来源 | 淘宝 / 京东 | 来源追踪缺失 | 可为空 |
| likes | 可选 | 点赞数 | 12 | 排序参考缺失 | 可为空 |
| answerCount | 可选 | 回答数 | 3 | 热度参考缺失 | 可为空 |

## 6. 字段识别流程

```text
读取所有 sheet / 表头
↓
自动匹配 question / answer 字段
↓
展示识别结果
↓
用户确认或手动修改字段映射
↓
确认后才能生成看板
```

如果自动识别失败，必须提供人工选择：

```text
请选择哪一列是“消费者的问题”
请选择哪一列是“他人的回答”
```

如果用户最终无法确认 question 或 answer，则阻断生成并提示：

```text
无法生成看板：请至少选择“消费者的问题”和“他人的回答”两个字段。
```

## 7. 数据清洗规则

```text
去除 question 和 answer 都为空的行
保留 question 有值但 answer 为空的行，并标记“无回答/回答缺失”
去除完全重复行
保留原始问题和原始回答，不要过度改写
统一空格、换行、全角半角
question / answer 长文本不要截断
```
