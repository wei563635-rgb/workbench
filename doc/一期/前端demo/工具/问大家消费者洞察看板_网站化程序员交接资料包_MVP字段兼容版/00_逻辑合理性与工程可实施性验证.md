# 逻辑合理性与工程可实施性验证

## 1. 验证结论

本交接资料包的方案逻辑合理，工程上可实施，适合作为第一版 MVP 开发依据。

核心闭环为：

```text
上传问大家数据源
↓
字段识别与人工确认
↓
数据清洗
↓
调用大模型生成标准 JSON
↓
JSON Schema 校验
↓
JSON 质检 Prompt 校验
↓
注入最终 HTML 母版
↓
在线预览 / 下载单文件 HTML
```

## 2. 逻辑合理性验证

### 2.1 输入假设合理

用户已确认问大家数据源格式可能不固定，但一定会包含两个核心字段：

```text
消费者的问题 question
他人的回答 answer
```

因此系统不应强制固定 Excel 模板，而应采用：

```text
字段别名自动识别
+
人工字段映射确认
```

这可以覆盖不同平台、不同导出格式、不同字段命名习惯。

### 2.2 分工逻辑合理

程序适合处理稳定、可规则化的任务：

```text
文件上传
字段识别
字段映射
空值处理
重复处理
数据类型转换
原始明细保留
JSON Schema 校验
HTML 注入与导出
```

大模型适合处理语义和业务判断任务：

```text
消费者问题理解
关注点归纳
人群/场景识别
购买阻力判断
推广图测图方向
详情页证据链
```

该分工能避免两类问题：

```text
程序硬做语义分析导致质量差
大模型处理表格清洗导致不稳定
```

### 2.3 页面复刻逻辑合理

最终看板不应由程序或模型重新设计，而应：

```text
固定最终 HTML 母版
只替换 dashboard-data 中的标准 JSON
```

这能保证页面结构、UI、交互、下钻、测图矩阵、详情页证据链和附录追溯稳定复刻。

### 2.4 质量保障逻辑合理

仅调用一次大模型生成 JSON，容易出现字段缺失、空泛结论、结构不稳定等问题。  
因此加入：

```text
JSON Schema 校验
+
JSON 质检 Prompt
+
质检不通过自动修正一次
```

这个流程能显著提升生成质量和稳定性。

## 3. 工程可实施性验证

### 3.1 技术实现成熟

所有关键能力都有成熟实现方式：

| 能力 | 可实施方案 |
|---|---|
| Excel/CSV 解析 | pandas / openpyxl / csv-parser |
| 字段识别 | 字段别名库 + 相似度匹配 + 人工确认 |
| 大模型分析 | OpenAI API / 其他支持 JSON 输出的大模型 API |
| JSON 校验 | JSON Schema validator |
| HTML 渲染 | dashboard-data 注入 |
| HTML 下载 | 后端生成单文件 HTML |
| 在线预览 | iframe / 静态 HTML 预览 |

### 3.2 MVP 范围可控

本方案明确第一版不做：

```text
黄金样例库
复杂权限
历史版本对比
模板管理后台
多人协作
投放数据回填
```

第一版只做上传、分析、渲染、预览、下载，工程范围可控。

### 3.3 主要风险与应对

| 风险 | 影响 | 应对方案 |
|---|---|---|
| 字段识别失败 | 无法分析 | 增加人工字段映射确认 |
| 大模型输出 JSON 不合法 | 前端无法渲染 | Schema 校验 + 自动修正 |
| 结论空泛 | 看板无业务价值 | JSON 质检 Prompt 拦截 |
| 数据量过大 | 模型上下文超限 | 先清洗压缩，必要时分批摘要 |
| HTML 无数据 | 页面只有壳子 | dashboard-data 强制校验 |
| 页面被重构 | 样式跑偏 | 固定最终 HTML 母版，只替换 JSON |

## 4. 建议开发优先级

### P0 必须开发

```text
上传文件
读取表头
自动识别 question / answer
人工确认字段映射
数据清洗
大模型分析
JSON Schema 校验
JSON 质检
HTML 母版注入
在线预览
下载 HTML
基础错误提示
```

### P1 可选增强

```text
生成记录
重新生成
下载 JSON
质量评分展示
简单历史列表
```

### P2 后续再做

```text
复杂权限
黄金样例库
模板管理
投放数据回填
多用户协作
版本对比
```

## 5. 最终验证结论

该方案符合用户当前目标：

```text
上传数据源
↓
经过大模型处理
↓
生成高质量标准 JSON
↓
套用最终满意样式
↓
输出数据看板
```

不包含过重的黄金样例库和复杂后台，适合作为第一版网站化 MVP。
