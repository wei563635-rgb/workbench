# 技术架构与部署方案

## 1. 推荐架构

```text
用户浏览器
↓
前端上传页面
↓
后端文件解析服务
↓
字段识别与人工确认
↓
数据清洗
↓
生成 rawDetails 原始明细底表
↓
调用大模型 API：生成标准分析 JSON
↓
程序执行 JSON Schema 校验
↓
调用大模型 API：业务质量质检
↓
不合格自动修正一次
↓
固定 HTML 模板渲染
↓
在线预览 / HTML 下载
```

## 2. 推荐技术栈

| 模块 | 建议 |
|---|---|
| 前端 | Vue / React / Next.js |
| 后端 | Python FastAPI / Node.js NestJS |
| Excel 解析 | pandas + openpyxl |
| CSV 解析 | pandas / csv-parser |
| 大模型 | 支持 JSON 输出和长文本分析的大模型 API |
| JSON 校验 | jsonschema / ajv |
| HTML 渲染 | 模板文件 + dashboard-data 注入 |
| 部署 | 内网服务器 / 云服务器 |

## 3. 大文件处理策略

```text
先由程序清洗和去重
只把 question / answer / 必要可选字段传给模型
必要时按批次摘要
最终合并为统一标准 JSON
完整 details 保留在后端和最终 JSON 中
```

## 4. 模型失败兜底

```text
JSON 解析失败 → 自动要求模型修正 JSON
Schema 校验失败 → 返回错误字段并自动修正
质检不通过 → 自动二次修正一次
连续失败 → 标记生成失败并提示人工处理
```

## 5. 部署建议

### MVP 内网部署

```text
单台服务器
前后端同机部署
SQLite 或简单文件存储
适合小范围内部试用
```

### 正式部署

```text
云服务器
PostgreSQL
对象存储
HTTPS
账号权限
日志监控
定期备份
```
